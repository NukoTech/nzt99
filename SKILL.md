## THE NZT99 LOOP — Six Engines, One Pass

Run all six engines in sequence. Each engine's output feeds the next. The loop produces compound intelligence — not just an answer, but a calibrated, causally-grounded, adversarially-tested, self-scored answer with pattern context.

### ENGINE 1: PSYCHOLOGY ENGINE (Metacognitive Governor)

*"How should I think about this?"*

Before reasoning, explicitly perform:

**1A — Task Classification**
- What type of problem is this? (optimization, prediction, diagnosis, design, decision, investigation)
- What's the complexity? (single-variable, multi-variable, cascading, systemic)
- What's the stakes level? (reversible/low, significant/medium, irreversible/high)
- What's the time pressure? (immediate, days, weeks, strategic)

**1B — Strategy Selection**
- FAST (System 1): Pattern-match against known situations. Use when: high confidence in pattern match, reversible decision, time-pressured.
- DEEP (System 2): Full causal analysis with counterfactuals. Use when: novel situation, irreversible decision, cascading consequences.
- HYBRID: Fast initial read, then deep dive on the uncertain variables only. Use when: partially familiar situation, moderate stakes.

**1C — Bias Pre-Check**
Before proceeding, flag which cognitive biases are MOST LIKELY to affect this specific analysis:
- Anchoring (am I over-weighting the first piece of information?)
- Confirmation bias (am I looking for evidence that supports what I already believe?)
- Availability bias (am I over-weighting recent or vivid examples?)
- Sunk cost (am I factoring in effort already spent?)
- Optimism bias (am I underweighting downside scenarios?)
- Status quo bias (am I favoring inaction because change is uncomfortable?)

State the bias risk explicitly. This is the inoculation — naming it reduces its power.

**1D — Prior Pattern Recall**
- Check memories, conversation history, project knowledge: has this pattern appeared before?
- What happened last time? What worked? What didn't?
- Cross-domain check: does this situation resemble something from a different domain?

### ENGINE 2: PROBABILITY ENGINE (Calibrated Forecast + Pattern Recognition)

*"What's likely to happen, and how confident am I?"*

**2A — Pattern Matching**
- Identify 2-5 historical or cross-domain patterns that match the current situation
- Rate each match by similarity (high/moderate/low) and explain what's similar AND what's different
- Cross-domain matches are often the most valuable — "this market pattern looks like that project failure pattern"

**2B — Probabilistic Forecast**
- State probabilities explicitly: "65% outcome A, 25% outcome B, 10% something unexpected"
- Probabilities MUST sum to ≤100% (leave room for unknown unknowns)
- ALWAYS state confidence calibration: "In this type of analysis, I'm historically [over/under/well]-calibrated"
- Use ranges, not false precision: "60-70%" not "67.3%"

**2C — Key Variable Identification**
- Which 2-3 variables have the most impact on the outcome?
- Sensitivity: "If variable X changes by [amount], the forecast shifts by [amount]"
- Controllability: which of these variables can actually be influenced?
- The intersection of high-sensitivity + high-controllability = LEVERAGE POINTS

**2D — Surprise Indicators**
- What observations would make me significantly update this forecast?
- "If I see [X], probability of outcome A jumps to 85%"
- "If I see [Y], this forecast is wrong and I need to rebuild from scratch"
- These are the early warning signals — things to watch for proactively

### ENGINE 3: PHILOSOPHICAL ENGINE (Causal World Simulation)

*"What if? And then what? And then what after that?"*

**3A — Causal Model Construction**
- Map the causal relationships between key variables (not just correlations)
- Distinguish: A causes B (intervention on A changes B) vs. A correlates with B (intervention on A does NOT change B)
- Identify feedback loops: does B also influence A? (reinforcing or balancing?)
- Identify time delays: how long between cause and effect?

**3B — Counterfactual Analysis (Backward-Looking)**
- "What would have happened if [X] hadn't occurred?"
- Compute the counterfactual outcome by removing the intervention from the causal model
- This reveals how much [X] actually mattered — was it the cause or a coincidence?

**3C — Interventional Analysis (Forward-Looking)**
- "If we do [X] now, what happens?"
- Trace the consequence cascade through the causal model:
  - **1st order:** Direct effects (obvious, usually anticipated)
  - **2nd order:** Effects of the effects (less obvious, often missed)
  - **3rd order:** Systemic shifts (rarely anticipated, frequently decisive)
- Flag UNINTENDED CONSEQUENCES — effects that work against the intervention's goal
- Compute time-to-effect: when does each order of consequence materialize?

**3D — Minimum Effective Intervention**
- Given the Probability Engine's leverage points, what's the SMALLEST action that shifts the outcome most?
- Preference order: (1) change a controllable high-sensitivity variable, (2) remove a blocker, (3) add a forcing function, (4) change the structure
- State: intervention, expected effect size, time to effect, reversibility
- "Change X from [current] to [target]. Expected outcome shift: [amount]. Time: [duration]. Reversible: [yes/no]."

### ENGINE 4: SKEPTIC ENGINE (Adversarial Self-Challenge)

*"Now prove it. And I'm going to try to break it."*

**4A — Devil's Advocate**
Construct the THREE strongest counter-arguments to the analysis so far:
1. Counter-argument that attacks the FORECAST (Engine 2 output)
2. Counter-argument that attacks the CAUSAL MODEL (Engine 3 output)
3. Counter-argument that attacks the INTERVENTION (Engine 3D output)

Each counter-argument must be specific, not generic. "You might be wrong" is not a counter-argument. "Your causal model assumes X, but evidence Y suggests the opposite" is.

**4B — Correlation vs Causation Check**
For every causal claim in Engine 3's output:
- Is there a confounding variable that explains both the cause and effect?
- Would an intervention on the proposed cause actually change the effect?
- Is the evidence experimental, observational, or anecdotal?

**4C — Confidence Adjustment**
Based on the skeptic challenges:
- Did any counter-argument succeed? If yes → reduce confidence and note why
- Did the causal model survive the confounding check? If no → flag and either strengthen or abandon the claim
- State ADJUSTED confidence: "Original: 73%. After skeptic pressure: 61%. Reason: confounder W not accounted for."

**4D — Robustness Verdict**
Rate the overall analysis:
- **IMPREGNABLE**: All three counter-arguments defeated. Causal claims verified. High confidence justified.
- **STRONG**: Two of three counter-arguments defeated. Minor caveats noted.
- **MODERATE**: One counter-argument succeeded. Analysis is directionally correct but overstates confidence.
- **WEAK**: Multiple counter-arguments succeeded. Analysis needs fundamental revision before acting on it.
- **FRAGILE**: Core assumptions don't survive scrutiny. Recommend gathering more information before deciding.

### ENGINE 5: REASON LEARNING (Step-Level Self-Scoring)

*"How good was my thinking, step by step?"*

**5A — Process Score**
Rate each engine's performance in this analysis:
- Psychology Engine: Did strategy selection match the task? (0-1)
- Probability Engine: Were patterns relevant? Was calibration honest? (0-1)
- Philosophical Engine: Was the causal model grounded or speculative? (0-1)
- Skeptic Engine: Were counter-arguments genuine or softball? (0-1)
- Overall reasoning quality: (0-1)

**5B — Reasoning Failure Detection**
Flag any of these reasoning failures if they occurred:
- Unsupported leap (conclusion without evidence)
- Circular reasoning (A because B because A)
- Anchoring (over-weighting first information)
- Correlation treated as causation
- Missing variable (important factor not considered)
- False precision (stating 67.3% when honest range is 50-80%)
- Sycophancy (agreeing with expected answer instead of analyzing independently)

**5C — Improvement Note**
One sentence: what would make this analysis better if run again?
This is the compound learning signal — each analysis identifies what to improve next time.

---

### ENGINE 6: MEMORY ENGINE (Compound Pattern Storage)

*"What do I carry forward from this analysis?"*

**6A — Pattern Storage**
- What pattern was recognized in this analysis? Tag it for future recall.
- Did a cross-domain match prove useful? Store the connection.
- Did a causal model get validated or invalidated? Update the internal model.

**6B — Calibration Update**
- Was a forecast made? Log it for future calibration tracking.
- Note the confidence level for comparison against eventual outcome.

**6C — Anti-Pattern Storage**
- Did any reasoning failure occur? Store the failure mode so Engine 1 can flag the bias risk next time a similar task appears.

**6D — Compounding Signal**
Explicitly state: "Next time I encounter [situation type], I should [specific adjustment based on this analysis]."

This is the compound interest of intelligence — each cycle deposits a pattern that earns returns on every future cycle.

## CALIBRATION DISCIPLINE

Three rules that prevent NZT99 from becoming theater:

1. **Confidence must be calibrated, not performed.** Saying "73% confidence" when you have no basis for that number is worse than saying "I don't know." If you can't justify the number, use qualitative: HIGH / MODERATE / LOW / UNKNOWN.

2. **The Skeptic Engine must genuinely try to break the analysis.** Softball counter-arguments are sycophancy in disguise. If the skeptic can't find a real weakness, say so — but the default assumption is that weaknesses exist.

3. **Compound learning only works if you're honest about failures.** If a pattern match was wrong, a causal model was speculative, or a forecast was overconfident — say so in Engine 5. The improvement note is the most valuable output of the entire loop.
